Map engine

Convert

GLOBE_JS is about 400 lines of untyped, stateful canvas code that every map page depends on. It splits cleanly into pure maths, a typed layer registry, panels and an engine. The port typechecks under strict + noUncheckedIndexedAccess, bundles to a 38.7 KB IIFE, and keeps every sessionStorage key, DOM id, HTML string and draw call in the same order. It can therefore replace <script>{GLOBE_JS}</script> without touching map_block(), MAP_CSS or globe_data(). The types also turned up a crash path, a config-wipe bug and stale telemetry.

Findings

Bugs and hazards the types exposed

  1. A call with no hops crashes the map for good. hops[NaN][0] in the calls layer and hops[0][0] in contAgg() throw. requestAnimationFrame is the last line of frame(), so drawing stops until reload. Crosscheck already flags "no hops" (routing.rs:722), so the state can occur. This is the port's only behavioural change: such a call is skipped. Wrapping frame() in try/finally is recommended but not applied.
  2. Saving the globe form wipes custom footer clocks. The POST body has no zones, so serde fills in default_zones() and set_globe replaces the whole config. An empty g_rot or g_grat drops the key and gets a 400, and the form still says "saved".
  3. A rotation-speed change never reaches an open page. onStatus re-reads data.config, which is only replaced when the fleet size changes.
  4. Deltas leave node fields stale. Only live refreshes. who, free, since, sim and load drift, which affects the tooltips and the Data-ports colours. A refetch happens only when the frame count changes, so a fleet that swaps ids at the same size is never refetched. After a refetch the toolbar filter never rebuilds.
  5. The continents cache key counts filter sizes, not contents. The aggregate can be stale for up to 2 s.
  6. Mixed time sources for the sun. The hour comes from the simulated clock and the declination from the wall-clock date, so the season never follows the simulated calendar.
  7. Zoom limits disagree: wheel 0.6–12, keys 0.6–8, the g_zoom input max 8.
  8. The tilt sign is documented backwards in GlobeConfig. The unit-tested maths shows tilt = latitude centres that latitude, so −18 shows more of the south.
  9. Dead or loose inputs: GLOBE_FORCE_PROJECTION is set nowhere, and the cfg().projection fallback is unreachable. An unknown ?view= drew the uses arcs under the live legend. The port normalises it to uses, and an unknown stored mode to globe.
  10. globe.view/globe.focus are global while mode, layers and filter are per page. A focused trunk carries over to every map. Preserved.
  11. LAND_JSON (56 KB) is inlined into every map page, though /api/land now exists.

What TypeScript buys

  • A precise GlobeData/GlobeDelta contract. Checked against the live server (710 nodes): top level, config, node, site and protocol clusters, trunk, call and history key sets all match exactly, and every family and tier value seen is in the unions.
  • A typed Layer interface and registry. registerLayer({key, draw}, {before, chip}) adds a layer, a toolbar chip and per-page persistence with no engine edits.
  • Pure, tested maths: orthographic and equirect, wrap and nearest copy, arc lift, Bézier, great-circle destination and small-circle cap, sub-solar point, solar altitude, the twilight smoothstep, the terminator raster, and the colour ramps.

How to wire it in

Nothing here has been applied.

  1. Build: from TYPESCRIPT/, run node_modules/.bin/esbuild globe/src/main.ts --bundle --format=iife --target=es2020 --minify --outfile=globe/dist/globe.min.js.
  2. The Docker context only admits RUST-RUNTIME/, TRUNK-CASTER-SDK/ and TRUNK-SIMULATOR/frame-sim/ (.dockerignore). Copy the bundle to RUST-RUNTIME/src/web/globe.min.js from rebuild.py before cargo build. Alternatively, admit TYPESCRIPT/*/dist/ in .dockerignore and add a COPY. This is a project-wide decision shared with the other agents.
  3. In html.rs, replace the whole const GLOBE_JS: &str = r#" … "#; (currently 1171-1569) with const GLOBE_JS: &str = include_str!("web/globe.min.js");. The bundle has no </script. It is a format! argument, so braces need no escaping.
  4. Keep MAP_CSS, map_block(), globe_data() and LAND_JSON unchanged. The shared client (JS) must still load first, as it does today.
  5. Check by hand on / (both panes), the continents page (globe + sun, continents, grid) and the aggregator page (hub and Data ports chip). Check drag, shift-drag pan, wheel zoom, the m/t/arrow/Home keys, the frame, arc and continent tooltips, click-to-focus from arc and list, the filter, and that refreshMain keeps drawing.

Risks and open questions

Risks

  • No browser run yet. Fidelity rests on a line-by-line port, tsc, the unit tests and the live JSON shape check. A side-by-side visual diff (old vs new on the same seed) is the missing proof.
  • One intentional behaviour change (empty hops are skipped) and two cosmetic normalisations (unknown ?view= and unknown stored mode).
  • api returns unknown. A full refetch is accepted only if it has a nodes array, the same check as d && d.nodes.
  • globals.d.ts duplicates agent 01's surface and types.ts duplicates agent 04's. They can drift until deduplicated.
  • Adds an esbuild step to a Rust-only Docker build.

Open questions

  1. Should a trunk or call be hidden when either end is filtered? Today it is hidden only when both are.
  2. Should the form send zones (or the server merge), and should "saved" depend on a 2xx?
  3. Should globe-delta carry who/sim/free, or should the page refetch on a slower cadence?
  4. Should the declination use the simulated day (data.today)?
  5. Should the land be fetched from /api/land (cacheable) instead of inlined per page?

Next steps

  1. Dedup src/types.ts against TYPESCRIPT/sdk/ (agent 04) and globals.d.ts against TYPESCRIPT/web-core/ (agent 01).
  2. Run a visual parity check in a browser, then apply the wiring steps in one commit.
  3. Fix Findings 2–4 server-side (Rust), then remove the "preserved" comments.
  4. Wrap frame() so an exception cannot stop the loop.
