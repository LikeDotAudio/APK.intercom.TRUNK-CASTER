Findings

Config handling

  1. Hand-edits are destroyed on a parse error. runtime.rs:134-149 (sites, globe) and relay.rs:16-26 write the built-in default over a file that fails to parse. One trailing comma in sites.json replaces 179 sites, and nothing is logged.
  2. The other configs silently fall back to defaults. fader.json (re-read every tick; the next POST writes the defaults back), vendor-policy.json and settings.json.
  3. Unknown fields are ignored. No deny_unknown_fields, so a misspelt key does nothing. The validator warns on every unknown key (none today).
  4. Two capital lists disagree. emulators.json / the Python world table have 56 capitals. sites.json has 54 capital-tier sites, and 11 emulator capitals have none: ABUJ PRET ADDI ACCR RABA ABUD DOHA TEHR BAGH ISLA DHAK.
  5. Accented names give mangled slugs (bras-lia, bogot, krak-w, medell-n, s-o-paulo) from the ASCII-only slugify. They are already referenced by fader.json.
  6. 4 of 5 emulator scripts missing (RTS stand-in). The RTS rename OID is a 99999 placeholder with no target. Doc drift on projection, Preference.kind and the sites.json location.

JSONL logs (real results)

  1. 3,989 glued records (labels 69, renames 3,865, gpio 55): {"seq":3243,…}{"seq":1852407,…} from two runtime boots appending at once. Cause: util.rs:133 writeln! on an unbuffered File writes the text and the newline separately. Fix in patches/util.rs.patch.
  2. LOG_CAP did not hold: renames.jsonl is 206 MB against a 100 MB cap, with no .1. The rename error is swallowed.
  3. About 260 MB of stale simulated lines (98.5-99.9%) that the current runtime no longer writes. Safe to archive.
  4. seq restarts at 1 every boot (renames: 29,902 resets), so it is not a key.

Build

  1. The bundles must be classic-script IIFEs: the core shares TC, api, esc with GLOBE_JS and onclick=, and reads the Rust-injected REFRESH_MS/BUILD. build.ts refuses any output containing </script.
  2. rerun-if-changed on a missing directory reruns build.rs on every build, which re-stamps TC_BUILD and reloads every page. The patch watches the 5 named files only when the feature is on. Node is never run from build.rs.
  3. 4 areas write .tsbuildinfo into their source folders. Unify on node_modules/.cache/tsbuildinfo/.

How to wire it in

Nothing below has been applied.

  1. Promote config/tsconfig.solution.json to TYPESCRIPT/tsconfig.json.
  2. git apply patches/package.json.patch, which adds build, build:min, validate-config and validate-logs. Add TYPESCRIPT/dist/ to .gitignore.
  3. git apply --ignore-whitespace the Cargo.toml, build.rs and html.rs patches. Plain cargo build is unchanged; --features ts-bundles serves the TS bundles. A/B each page; each #[cfg] pair can flip on its own.
  4. Apply the Dockerfile and dockerignore patches: a node:24-bookworm-slim web stage (npm ci, typecheck, build), then cargo with the feature.
  5. Apply rebuild.py.patch: ts_build() runs typecheck, validate-config and build before cargo check --features ts-bundles, and skips TS when npm is absent.
  6. First and independently: apply util.rs.patch, then stop the overwrite-on-parse-error in runtime.rs:134-149 and relay.rs:16-26.

Risks and open questions

  • Parity depends on areas 01-03. The feature flag keeps the inline JS as the default until A/B passes. Unminified bundles are larger (globe 67 KB vs 45 KB), so use build:min in Docker if page weight matters.
  • The patches target today's working tree, which another session is editing. They are anchored on const names; regenerate with tools/mkpatch.cjs.
  • types.ts mirrors Rust by hand and will drift. Dedup with sdk/ (agent 04) and add a golden round-trip of Rust defaults.
  • Open: which capital list is canonical (54 vs 56)? Migrate accented slugs or freeze them? Move bad configs aside or only refuse to write? Why did two runtimes share one TRUNK root at 13:23Z?
