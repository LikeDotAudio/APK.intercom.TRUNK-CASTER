Broker core: routing, runtime tick, ports

Keep in Rust

Keep the server core in Rust. Node would not improve anything in it: it has one Mutex<Runtime>, OS threads for HTTP, WebSocket and Ward-Beck, a tick that does a lot of computing, a single small binary and 25 tests. The real problems are in the algorithms and are fixed in Rust. The route finder (direct or via, which caster to use, lease, park, sweep, reclaim) is now a pure TypeScript module. The browser can use it to preview a route before asking for it, and its behaviour matches the Rust code.

Findings

  1. The via-2 search is O(F²·T) and runs while holding the global lock (routing.rs:492-519, 461-480, 334, 280). With the live 710 frames, every request that fails direct and one-frame-via evaluates about 500k paths. Each one scans all trunks, and every feasible plan is collected before one is kept. Seeks do the same (runtime.rs:1667). Timings for a literal JS copy:
    • 100 frames: 127 ms
    • 200 frames: 1.0 s
    • 400 frames: 8.6 s
    • 700 frames: about 45 s (estimated)
    That is seconds per denied request even in Rust, with HTTP, WS and Ward-Beck stalled. The TS port gets the same answers in 1.9 ms. It uses a per-pass pair index, skips every second hop once the first hop is infeasible, and buckets plans by how many new trunks they need. The Rust code can copy all three.
  2. Reclaim releases only one red line (runtime.rs:983-1003, routing.rs:692). If that line shares a trunk with other calls, no caster is freed. The request is then denied while other red lines still hold the bandwidth. A test reproduces this.
  3. Picking up a parked line skips the caller rules (runtime.rs:957-975). It ignores the requested ports and keeps the old direction and id. It does not rename the ports after the new caller and does not count as a grant. It passes hold_seconds unclamped (the route path clamps it with max(0) at line 940).
  4. A parked line lives one to two sweep periods. sweep(last_sweep) releases only lines parked before the previous sweep (runtime.rs:1712). This may be an intended grace period.
  5. Crosscheck is O(C²) because of the port-clash check (routing.rs:753), and it runs every 5 sim-seconds. That is 54 ms on the live 1,029 connections and about 400M comparisons at the stress preset's 20k.
  6. Errors are classified by string matching (e.contains("no capacity"), runtime.rs:983), and nothing records why a request was denied. The live counters show 24.05M denied against 2.29M granted (91%).
  7. Two smaller points: create_trunk indexes [0] and can panic if its invariant is broken (routing.rs:592). The reclaim_for hop filter looks asymmetric but is correct.
  8. Parity on live data: the TS router loaded the real state.json (710 frames, 1,005 trunks). Crosscheck passed 1,029/1,029 with 0 failures. It also planned 2,000 random pairs in 1.66 s.

How to wire it in

None of these steps has been applied.

  1. Golden parity. Add #[test] #[ignore] fn dump_golden() to routing.rs tests:
    • Build seeded random fleets: 4-10 frames, 1-3 casters, 1-3 channels.
    • Run 200 ops: route 70%, release 20%, expire and sweep 10%.
    • Write the results in the GoldenFile shape to TYPESCRIPT/routing/golden/rust-dump.json.
    • Add one TS test that replays the file when it exists.
  2. Types. Replace types.ts with re-exports from agent 04's sdk/ once it exports Connection, Trunk, Shape and AllowedTrunk.
  3. Browser bundle. Run esbuild routing/src/request.ts --bundle --format=esm --platform=browser. Leave out golden.ts, which uses node:fs.
  4. Page. Take GET /api/state (http.rs:510, a superset of RouteState) and call preview(new Router(state), req, ctx). The page can then show direct, via or denied, with hops, before the user presses Request. allowedTrunks(from, to, 12) gives the same answer as /api/panel-seek without a round trip.
  5. Rust fixes, after the concurrent runtime session lands:
    • PlanIndex, hoisting and buckets in via_plans;
    • a HashMap for the crosscheck clash test;
    • a reclaim loop;
    • port rename and hold clamp on pick-up;
    • a RouteError enum and per-reason denial counters.
    Regenerate the golden file in the same PR.

Risks and open questions

  • Drift between two implementations. This is fixed only once the Rust dumper exists. Until then, parity rests on the hand-encoded assertions, the fuzz test and the live crosscheck.
  • /api/state is the whole state. That is about 1k connections now and up to 20k under stress. Cache it or add a slimmer endpoint for previews.
  • Preview accuracy depends on the client's sim_time. If it lags the server, lease and red decisions can differ.
  • Is the extra sweep period for parked lines an intended grace period?
  • Should a picked-up line rename its ports and count as a grant?
  • Should reclaim keep going until the request fits?
  • Where does the browser bundle live: the pages area or TRUNK-GLOBAL/js?
