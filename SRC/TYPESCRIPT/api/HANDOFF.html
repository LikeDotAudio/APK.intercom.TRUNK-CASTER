Findings

Bugs and hazards in the original

  • Path traversal through request ids. POST /api/request {"id":"../../x"} writes TRUNK-USERS/../../x.json (runtime.rs:948, users.rs:10), and /api/release deletes interface/<id>.json (runtime.rs:1066). This is reachable from any web page because of ACAO: * and simple text/plain POSTs, and from the LAN because Docker publishes 0.0.0.0:8080. Found by reading the source; not exploited.
  • Rust SDK HttpClient::rename always fails. It expects Rename, but the server returns RenameDispatch[] (client.rs:53 vs http.rs:490).
  • The WS sends no snapshot on connect, and frames come only once per tick. A tick takes about 2–20 s under load, so the first status arrived after 2.4–8.4 s.
  • globe-delta is not a delta. Every 2 s it resends about 790 KB (the full trunkList, callList, history and clusters). Its live and parked maps leave out zeros, so merging key by key leaves stale counts.
  • Validation is inconsistent. Malformed JSON is accepted as {} on capture/start, fader/quick and fader/preset. A missing id gives 400 on release but 404 on bookings/cancel. set_fader I/O errors are 500 on two routes and 400 on the third.
  • Denials come back as 200 (Reply.status:"denied"). Any non-GET to an unknown path, including OPTIONS, is 405, so CORS preflight always fails. Bodies over 4 MiB are silently truncated.
  • Path ids are not percent-decoded. /analyzer?id= is not decoded either, while /panels/editor?frame= is. A trailing slash turns /api/device/ into a generic 404.
  • Mixed content types: JSON, text/markdown (/api/report) and text/plain (/api/wardbeck, /api/checkin). Errors are always JSON {error}.
  • The WS broadcast holds the runtime lock with an 800 ms write timeout per client, so one slow socket stalls the tick. HTTP calls block for up to a full tick on the same mutex; a 2 s probe timed out once.
  • Internal state leaks: /api/state includes the private next_trunk field.
  • Newest-first vs oldest-first: status.log and status.wardbeck are newest first, while /api/log and /api/wardbeck are oldest first.

What TS buys

Every route is checked at compile time: wrong path, missing :id, wrong POST body and text-vs-JSON are all type errors. The ad-hoc json! shapes that had no schema now have one, and the merge rules for the stream are written down in code.

How to wire it in

None of this has been applied.

  1. When TYPESCRIPT/sdk/index.ts lands, re-export every @sdk type from it in api/types.ts, then re-run tsc -p api.
  2. Add {"path":"api"} to the root project references.
  3. In the page bundles, replace the inline api() helper and connectWs() (html.rs:174–182) with createClient({baseUrl:''}) and connectTelemetry({seed:()=>tc.get('/api/globe'), onStatus:applyStatus, onBuildChange:reload}).
  4. In CI, run smoke.ts (it passes with no server and exits 1 on drift), and regenerate openapi.json from openapi.ts.
  5. Rust follow-ups, owned by whoever holds http.rs:
    • sanitise ids;
    • fix HttpClient::rename;
    • send a snapshot frame on WS accept;
    • stop resending unchanged history every 2 s;
    • answer OPTIONS or drop ACAO: *.

Risks and open questions

  • routes.ts is kept in step with the Rust match by hand, and /api/land arrived mid-audit to prove it. A CI grep diff is recommended.
  • The @adhoc shapes have no Rust struct, so any edit to a json! literal silently changes the contract.
  • Param routes refuse ids that need escaping. That is correct for the server today, but it will throw if ids ever contain spaces or non-ASCII characters.
  • Open: are the alias pairs deliberate (/api/report=/report.md, /home=/about, /panels=/lights, …)?
  • Open: should globe-delta become a real delta?
  • Open: is publishing on 0.0.0.0 intentional?
