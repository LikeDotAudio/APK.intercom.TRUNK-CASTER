Findings

  1. High: JSON inside <script> without </ escaping (stored XSS). window.GLOBE_DATA={data} (line 1164) carries who and why straight from /api/request. serde_json does not escape <, so a who of </script><script>… runs on every globe view. The same pattern appears in LIGHTS0 (1732) and RELAY_MATRICES/RELAY_BOUND (3240). There are 8 such holes.
  2. High: esc leaves ', but values go into single-quoted JS strings in on*= handlers. There are 13 lines with 18 holes. In racks (line 3115), connect('{}',{},'{}') takes a port name set through /api/rename, so a name of x');alert(1);// runs when someone clicks it.
  3. Medium: raw holes fed from config. These are the badge emoji and colour, stroke:{col}, about 12 serde_json::Value Display holes, the chart {color} and the nav labels.
  4. tile() escapes its label but not its value.
  5. Quirks the ports reproduce: {:.N} rounds exact ties to even (fmt_num(0.25)=0.2), while JS toFixed rounds them up. fmt_num(99.95)=100.0. hm(23.9999)=24:00, because hm lacks the % 86_400 that hms has, which is a real bug in the footer clocks. Legend widths use UTF-8 bytes. lines/trim_end handle CRLF, NEL and BOM differently from JS. String order is by code point, not UTF-16 unit. f64::max ignores NaN.
  6. What TS gains: one escaping rule enforced by the SafeHtml type, charts that can be reused when telemetry refreshes the page, and renderers that can be tested on their own. What Rust SSR keeps: static snapshots that work without JS, and first paint.

How to wire it in

None of these steps has been applied.

  1. Rust fixes first: add ' → &#39; to util::esc. Add a json_script() helper that escapes <, U+2028 and U+2029 as JSON escapes, and use it at the 8 window.X={..} holes. Escape the badge and Value holes.
  2. Add charts/src/users-page.ts as an entry in agent 01's web-core esbuild config.
  3. In Rust, wrap the users_page body in <div id="users-root"> and keep SSR for first paint and the static snapshot.
  4. Call mountUsersPage(root).refresh() from web-core's telemetry handler instead of reload(). Use web-core's DOM morph if it has one.
  5. In CI, run gen-golden.ts and then the tests. Any diff in golden.json means a renderer in html.rs changed.
  6. Move these to shared code to remove duplicates: the UserRecord/How/Series types and oceanBetween go to sdk/ (agent 04), and TOPIC_COLOURS goes to web-core (agent 01).

Risks and open questions

  • html.rs is being edited at the same time, so line numbers will drift. The generator extracts functions by name, so it keeps working.
  • Rendering on the client drops the no-JS static snapshot unless SSR stays for first paint.
  • The charts keep Rust's escaping and leave ' unescaped. That is safe because their values only land in text nodes and double-quoted attributes.
  • Swapping innerHTML loses the scroll position unless web-core morphs the DOM instead.
  • The proof does not add the sash columns or pop-outs. Those belong to agents 01 and 03.
  • Open: can anyone other than operators reach /api/request and /api/rename? Should the static snapshots become JSON plus a shell? Should hm gain % 86_400 on both sides?
