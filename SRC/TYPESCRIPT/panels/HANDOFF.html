Convert

Findings

  • F1 bug, fixed. trunk_panel.py:236-243: retargeting an active TALK key never re-evaluates the mic gate, so the mic keeps streaming with no talk key latched. A test covers the fix.
  • F2 bug, hardened. :117-118: a malformed HELLO_ACK raises KeyError and silently kills the link thread, leaving the panel on "connecting" forever.
  • F3 bug, kept faithful. streamdeck_emulator.py:149: the green fallback is dead code because colors() always sets active to red, so a listen key without colors.active lights red. It is latent, since the shipped decks set green.
  • F4. close() releases talks but not listens or trunk calls. Latch state is never reconciled with the server, and latched/state are mutated across threads with no lock.
  • F5 stale. The trunk_panel docstring and the int(port or 18100) fallback predate the 20000 + 256·n series scheme. --matrix myhost with no port connects to 127.0.0.1:18100.
  • F6 doc drift. The README says :8080 on the same line as --api …:8180. It also says color where the schema says colors. The schema says MK2 keys are 96 px, but they are 72 px.
  • F7 contract gap. connect.json feedback fields omit remote, which the emulator needs to light call keys.
  • F8. The schema promises hold_to_latch_ms, icon, serial and encoder actions, but the emulator implements none of them.
  • F9 data. In streamdeck-xl.json:17 the "ALL CAMS" key targets only CAM07.
  • F10 audio. Decimation is a boxcar filter (aliasing) and upsampling is sample-repeat (imaging). The jitter queue is 12 frames with drop-oldest, no prefill and no drift handling. Incoming-call age mixes the matrix clock with the local clock. numpy is not installed on this PC, so trunk_panel.py has no audio here today.
  • F11. The button API is unauthenticated GET-with-side-effects. That is fine for a lab network, and both TS UIs bind to 127.0.0.1 only.

How to wire it in

Nothing below has been applied.

  1. Add panels to the root TYPESCRIPT tsconfig references.
  2. Run both CLIs against the real rts_intercom_sim.py (--api http://127.0.0.1:8180 --matrix LOND, --matrix 127.0.0.1:22304). Compare the --test-seconds lines with the .py output.
  3. Update the README "Try it" section and connect.json audio_for_the_operator.command, and fix F6/F7 in the same edit.
  4. Replace the local tc-protocol.ts and wire types with imports from TYPESCRIPT/sdk (agent 04).
  5. Retire the two .py files only after step 2 passes with real audio on the target PC.

Risks and open questions

  • Not yet run against the live simulator. The response shapes come from reading its source.
  • The browser bridge needs an open tab and mic permission, even for listen-only, because speaker blocks are clocked by mic blocks. The context must run at --rate.
  • The DSP uses float64 means where numpy used float32, so output can differ by about 1 LSB. It is not bit-identical, but the difference is inaudible.
  • Question: should the schema's action carry the 8 GPIO key functions (blink panel, check lights, set latch, set listen, unset latch, clear, last caller, ping)?
  • Question: should lint enforce the 6 / 8 / 16-char label widths (emoji allowed)?
  • Question: fix F3 now, or keep it faithful until the Python is retired?
  • Question: is a headless ffmpeg audio device needed for TRUNK-RELAY?
